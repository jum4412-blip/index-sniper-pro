## EC2 최초 설치 또는 수동 업데이트

EC2의 `ubuntu` 사용자로 접속하여 아래 블록을 실행합니다. `sudo bash ...`로 전체 설치기를 실행하지 않습니다. 필요한 systemd 등록 단계에서만 `sudo`를 사용합니다. **기존 `.git`이 있는 `~/index-sniper-pro`를 사용합니다.** 과거에 별도로 풀어 둔 `~/btc_eth_probability_v1_git` 같은 비 Git 작업 폴더에서 `git pull`을 실행하지 않습니다.

```bash
(
set -e
REPO="$HOME/index-sniper-pro"
git -C "$REPO" rev-parse --git-dir >/dev/null
git -C "$REPO" fetch origin main
COMMIT="$(git -C "$REPO" rev-parse FETCH_HEAD)"
INSTALLER="$(mktemp)"
trap 'rm -f "$INSTALLER"' EXIT
git -C "$REPO" show "$COMMIT:trading_lab_ec2/deploy.sh" > "$INSTALLER"
bash "$INSTALLER" "$REPO" "$COMMIT"
)
```

설치기는 해당 커밋의 새 폴더만 `git archive`로 추출합니다. 기존 작업 브랜치에서 `git pull`, `checkout`, `reset --hard`, `clean -fd`를 실행하지 않습니다. 설치 전에 단위 테스트를 실행하고, 코드와 실행 기록을 다른 위치에 둡니다. 원격 저장소의 변경을 자동으로 실시간 배포하지 않습니다.

**설치 직후 수집기는 시작하지 않으며 부팅 자동실행도 꺼진 상태입니다.** 업데이트 때도 이 수집기만 중지하고, 로컬 DB 백업 후 코드를 교체합니다. 공개 API 검사와 명시적인 `start` 명령 후 다시 실행합니다. 실패 시 기존 실매매 서비스를 건드리지 않지만, 이 관찰 수집기는 정지 상태로 남을 수 있습니다.

```bash
~/lab1030 doctor
```

BTC·ETH의 ticker 및 네 시간대 검사 결과가 `OK`인지 확인합니다. API 계정 키는 필요 없습니다. 실제 서버에서 실패하면 다음 단계로 강행하지 말고 결과를 확인합니다. `doctor --offline`은 네트워크를 검사하지 않으므로 실연결 성공으로 해석하지 않습니다.

```bash
~/lab1030 start
```

`start`도 공개 API를 다시 검사한 후 `lab1030-observer.service`와 `lab1030-backup.timer`만 활성화합니다. 첫 수집 주기가 끝난 뒤 확인합니다.

```bash
~/lab1030 status
~/lab1030 service-status
```

실제 거래소에 주문하거나 1,030 USDT를 이동시키는 단계는 없습니다. 터미널을 닫아도 systemd 서비스는 실행됩니다. EC2 인스턴스 자체가 실행 중이어야 하며, 서버가 종료/삭제되면 프로그램이 계속 작동할 수 없습니다.

초기 700 USDT 장부를 자동으로 만들거나 330 USDT를 자동 이체하지 않습니다. 이전 오프라인 패키지의 `demo`는 가상 숫자로만 계산합니다.

공개 API는 각 종목/시간대에서 기본 최근 200개 봉을 조회하고 중복 없이 누적합니다. 진행 중인 봉은 제외합니다. 최초 시작 이전 모든 기록을 수집한 것이 아니며, 장시간 중단으로 조회 범위를 넘어선 누락은 `DATA_GAP_REVIEW`로 남습니다. 누락 봉을 0이나 선형 보간으로 채우지 않습니다. 200개 5분봉은 약 16시간 40분의 범위입니다. 오래된 구간은 별도 과거 조회 절차가 필요합니다.

가격 시세 샘플은 기본 30일, 처리 주기 요약은 30일 유지하고 마감봉과 정정 이력은 자동 삭제하지 않습니다. 최신 봉 값이 정정되면 이전 값/새 값/관측 시각을 남깁니다. 실제 전략 검증 시에는 그 시점에 관측 가능했던 버전을 사용하도록 별도 재생 엔진을 만들어야 합니다.

반환된 펀딩비율은 **시장의 비율 데이터**입니다. 사용자 계좌에서 실제 지급·수취한 펀딩 금액이 아닙니다.

**EC2 전체 장애, DNS 전체 장애 또는 Telegram 연결 장애 시 이 프로그램 스스로 알림을 보내지 못할 수 있습니다.** 워치독은 같은 서버의 멈춘 프로세스 재시작을 위한 장치일 뿐, 외부 장애 감시 서비스가 아닙니다.

## 백업과 보안

매일 한국시간 03:10 이후 최대 5분의 임의 지연 후 SQLite 온라인 백업을 실행합니다. 성공한 복사본 최근 7개만 남깁니다. 원본 DB를 WAL 파일 없이 단순 `cp`하는 대신 SQLite backup API를 사용합니다. 백업 전에 여유 공간을 확인하며, 여유가 부족하면 기존 데이터를 지우지 않고 실패합니다.

**이 백업은 같은 EC2 디스크에 있습니다. 인스턴스/볼륨 손실에 대한 재해 복구가 아닙니다.** 장기 운용에는 별도의 EBS 스냅샷 또는 검증된 외부 백업을 설정해야 합니다. 이 패키지는 AWS 계정에 접속하지 않으며, 유료 리소스나 스냅샷 정책을 생성하지 않습니다. 비용과 보존 기간은 별도 결정 사항입니다.

공개 시장 수집용 Bitget API 키는 만들 필요가 없습니다. 실매매 인증 키를 넣을 설정도 없습니다. 새 네트워크 수신 포트를 열지 않습니다. 외부 의존 패키지를 설치하지 않으며 기존 봇의 가상환경을 재사용하지 않습니다. 그래도 동일한 EC2의 CPU/디스크/네트워크를 공유하므로 완전한 장애 격리는 아닙니다.

## 검증 범위

`TEST_REPORT.md` 참조. Python 3.13.5에서 원래 계산/장부 41개와 새 관찰/배포 61개, 합계 102개 테스트를 실행했습니다. systemd 유닛 문법·참조 검사는 통과했습니다. 실제 EC2 설치/서비스 재시작/실거래/Telegram 전달을 실행한 것은 아닙니다. 제작 환경의 외부 DNS 접속이 실패하여 Bitget API 실제 연결은 검증되지 않았습니다. 제공된 `doctor`는 이를 사용자의 EC2에서 확인하는 단계입니다.
