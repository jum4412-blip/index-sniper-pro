# 1,030 USDT 자동매매 연구·회계 기초 패키지

작성 기준: 2026-10-13. 예제 숫자는 가상 값입니다. 현재 시세나 계좌 조회 결과가 아닙니다.

## 이 파일로 할 수 있는 것

구조 보호선까지의 거리와 위험예산으로 주문 크기를 계산하고, 입출금을 수익에서 분리한 기준가(NAV) 장부를 시험합니다. 검증 상태에 따른 운용자금 증액 한도도 계산합니다. 표준 라이브러리만 사용하며 API 키나 인터넷 연결이 필요하지 않습니다.

**실매매 프로그램이 아닙니다. 거래소 연결, 시장 데이터 수집, 백테스트, 매매 신호, 보호 주문, 주문 전송, 텔레그램 연동, 실제 자금 이체는 구현되어 있지 않습니다.** `micro`와 `standard`는 여기서는 계산 예제의 위험 수준을 뜻할 뿐, 실제 주문 모드가 아닙니다. 기존 봇이나 EC2 서비스를 수정·중지하지 않습니다.

## 시작

압축을 푼 뒤 `trading_lab_1030` 폴더에서 실행합니다.

```bash
python3 -m unittest discover -s tests -v
python3 cli.py demo
```

제공 환경에서 Python 3.13.5로 41개 단위 테스트를 통과했습니다. 다른 서버에서는 위 명령으로 재확인해야 합니다. Python 3.10 이상을 사용하도록 작성했지만, 이 패키지에서 실제로 실행 확인한 버전은 3.13.5입니다. 테스트 통과는 계산 예제의 검사 결과이지 수익성·거래소 호환성·실거래 안정성 인증이 아닙니다.

`demo`는 메모리 안에서 동작하며, 가상 BTC 가격 80,000, 보호선 78,800, 가상 비용 여유 0.2%, **가상 주문 단위** 0.0001을 사용합니다. 이 주문 단위와 최소 주문 금액은 Bitget에서 조회한 값이 아닙니다.

## 로컬 장부 사용 예시

아래 금액과 날짜는 가상 예제입니다. 실제 기록에는 실제 거래소 평가액과 입출금 시각을 사용해야 합니다. 장부 파일에는 거래소 API 키를 넣지 않습니다.

```bash
python3 cli.py append --db sample.sqlite --id initial-001 \
  --timestamp 2026-10-13T09:00:00+09:00 --kind INIT --amount 700

python3 cli.py append --db sample.sqlite --id mark-001 \
  --timestamp 2026-10-14T09:00:00+09:00 --kind MARK --amount 630

python3 cli.py append --db sample.sqlite --id deposit-001 \
  --timestamp 2026-10-15T09:00:00+09:00 --kind FLOW --amount 200 --pre-equity 630

python3 cli.py report --db sample.sqlite
```

결과는 평가액 830, 누적 순입금 900, 거래손익 -70, 입금 영향을 제거한 수익률 -10%입니다. 200을 입금해도 손실률이나 이전 최고 기준가는 리셋되지 않습니다.

`INIT`는 최초 한 번, `MARK`는 그 시점의 전체 운용 평가액, `FLOW`는 실제 입출금입니다. `MARK`의 `amount`는 그날 손익이 아니라 **미실현 손익까지 반영한 총 평가액**입니다. `FLOW`에는 반드시 입출금 직전 평가액이 필요합니다. 여러 입출금은 각각 기록해야 합니다.

운용계좌 밖 예비금에서 운용계좌로 옮긴 돈은 이 장부에서는 `FLOW`지만, 프로젝트 전체로 보면 내부 이동입니다. 이를 새 외부 입금으로 다시 합산하지 않아야 합니다. 서버/API 비용은 이 장부에 자동 반영하지 않습니다. 이미 거래소 평가액에 반영된 수수료와 펀딩비도 다시 빼지 않습니다.

같은 ID·같은 내용의 재입력은 중복 반영되지 않습니다. 같은 ID에 다른 내용을 넣거나, 이미 기록한 시각보다 과거 이벤트를 뒤늦게 끼워 넣으면 오류가 발생합니다. 누락된 과거 자료는 원본을 보존한 채 정렬·검증해서 별도 재생 절차로 복원해야 합니다. 기존 장부를 지워 손실을 없애서는 안 됩니다.

## 아직 없는 안전 기능

계산기의 `account_reconciled=True` 같은 입력은 외부에서 검증했다고 전달하는 표시일 뿐, 실제 거래소 검증을 수행하지 않습니다. `demo`는 가상 상황을 만들기 위해 이 값들을 True로 둡니다. 운영 봇에 연결할 때는 실제 어댑터와 검사 없이 True로 고정하면 안 됩니다.

8% 낙폭 계산기는 신규 크기 제안을 차단할 뿐 보유 포지션을 청산하지 않습니다. 실전의 긴급 청산, 보호 주문 확인, 재접속 복구, 실제 수수료·펀딩 장부, 영구적인 중지 플래그는 별도 구현·시험해야 합니다. 실제 손실은 계획 예산이나 설정한 낙폭 기준을 초과할 수 있습니다.

이 패키지는 작은 연구용 시작점입니다. 기존 `NATIVE_CHILD_OWNERSHIP_MISMATCH` 등을 해결하거나 거래소 포지션을 인계하는 기능은 없습니다. 현재 포지션·조건부 주문·레거시 프로세스 상태를 먼저 확인해야 합니다.
