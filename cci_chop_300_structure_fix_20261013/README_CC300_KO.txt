   중지합니다. 자동 추가매수로 목표 수량을 채우지 않습니다.
4. 300은 체결 전 목표 명목 증거금입니다. 거래소 수량 단위, 체결가,
   마크 가격과 수수료 때문에 앱 표시 증거금이 정확히 300은 아닐 수 있습니다.

익절·손절과 보호
- 고정 +n% 익절 / -1% 손절은 없습니다. CCI·CHOP은 진입 필터입니다.
- 기존 완료봉 구조 규칙을 유지합니다: 주·일 방향 전환, 4시간 확정 구조
  이탈, 기존 또는 새 구조 보호선을 통과한 5분 완료 가격에 따라 청산합니다.
- 진입 시 4시간·1시간의 확정된 지지·저항 구조에서 보호 가격을 계산합니다.
  이 가격은 거래소 측 마크 가격 트리거 시장가 손절로 부착합니다.
- 유리한 새 구조가 확정되면 보호선을 좁히고 거래소 수정 결과를 재조회합니다.
  구조가 깨지면 손익 부호에 관계없이 청산합니다. 수익 중이면 익절,
  손실 중이면 손절이며 고정 익절 목표가를 별도로 두지 않습니다.
- 주문·보호 이상 시 안전 관리는 유지합니다. 일 2%, 주 5%, 계좌 고점 대비
  10% 위험 제한은 신규 진입 중지용으로 유지되며 -1% 가격 손절이 아닙니다.

  거래소 확인이 오래됐거나 조회가 실패하면 실제 보유를 '확인 필요'로 표시합니다.

EC2 설치
ZIP을 풀면 최상위에 cc, cci_chop_v1, tests, README_CC300_KO.txt가 있습니다.
GitHub index-sniper-pro 저장소의 main 루트에 이 항목들을 올리세요.
credentials.env, connection.json, data 디렉터리는 업로드하거나 덮어쓰지 마세요.

아래 명령을 EC2 ubuntu 터미널에 붙여 넣으세요:

(
set -euo pipefail
live_dir="$HOME/btc_eth_probability_v1_git"
stage_dir="$(mktemp -d "$HOME/cci_chop_update_300.XXXXXXXX")"
cd "$HOME/index-sniper-pro"
git fetch origin main
git archive --format=tar FETCH_HEAD cc cci_chop_v1 tests README_CC300_KO.txt |
    tar -xf - -C "$stage_dir"
bash "$stage_dir/cci_chop_v1/deploy/update_ec2_flat.sh" "$live_dir"
)

업데이트 절차는 새 폴더에서 테스트를 먼저 실행하고 거래소 전체 포지션·미체결
주문·전략 주문이 모두 0인지 확인한 뒤 기존 서비스를 종료합니다. 다시 빈 계정을
확인한 뒤 기존 코드를 별도 압축 백업하고 코드만 교체합니다. 키는 복사하지 않습니다.
recover-flat이 SQLite와 이전 설정을 백업하고 청산 정산을 확인한 뒤
300 × 5 설정으로 이전합니다. 계좌·거래·손실 기록은 삭제하지 않습니다.
doctor/알림 검사, 별도 arm, 서비스 시작까지 사용자 요청 범위에서 실행합니다.

BLOCKED가 나오면 이후 명령은 실행되지 않습니다. 특히 거래소 현재 보유가 없어도
실제 미체결 주문이나 보호 주문이 남아 있으면 업데이트를 중단합니다.
이를 통과하려고 DB·손실 기록을 지우거나 모르는 주문을 취소하지 마세요.
코드 교체 후 일시적인 조회 실패가 발생했다면 다음 명령으로 복구부터 재시도합니다:
cd ~/btc_eth_probability_v1_git
./cc recover-flat --mode live
./cc doctor --mode live
./cc arm --mode live --allow-unvalidated-live
sudo systemctl start cci-chop-live.service

운영 확인:
cd ~/btc_eth_probability_v1_git

./cc notify-now --mode live
sudo journalctl -u cci-chop-live.service -n 60 --no-pager

검증 범위
오프라인 코드 테스트는 실제 Bitget 신규 FOK 주문·보호 수정의 성공이나 미래
수익을 승인하는 검증이 아닙니다. sizing 변경 후 전략 성과를 새로 평가해야 합니다.
기존 모델의 수익성·전진 검증 승인 플래그는 false로 유지합니다.
이 패키지를 만드는 과정에서 실매매 주문·주문 취소·텔레그램 발송은 하지 않았습니다.
